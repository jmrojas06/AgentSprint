## Description

Hallazgo de review de TK-17: `packages/core/src/storage.ts` `_atomicWrite` usa nombre tmp fijo `${file}.tmp` sin lock. Dos procesos escribiendo a la vez pueden colisionar en el mismo tmp o perder entradas por el read-modify-write de `appendLearningsSection`. Fix: tmp único por escritura, cleanup en error y lock simple por archivo para secciones críticas.

## Acceptance criteria

- [x] El nombre del archivo temporal es único por escritura (incluye pid y bytes aleatorios), evitando colisiones entre procesos
- [x] La escritura usa rename atómico y limpia el archivo temporal en error (try/finally)
- [x] Las secciones críticas read-modify-write (appendLearningsSection, setTaskStatus) están protegidas contra escritura concurrente sin perder entradas
- [x] No cambia el formato de ningún archivo persistido (.md, .yaml, .json)
- [x] Tests que simulan escritura concurrente (dos llamadas paralelas a appendLearningsSection / updateTask) verifican que no se pierde ninguna entrada y que no quedan archivos .tmp residuales

## Notes

- [2026-08-26T19:03:31.116Z] (agent) Implementado escritura atómica segura: _atomicWrite usa tmp `${file}.${pid}.${randomBytes(4).hex}.tmp` con rename atómico y cleanup en finally (try/finally). Elección de lock: lockfile `${file}.lock` creado con flag 'wx' (exclusivo atómico), retry cada 25ms hasta 2000ms timeout, usando Atomics.wait para no spinear CPU. Se descartó mutex solo in-process porque el riesgo multi-proceso es real (CLI, server y MCP pueden escribir el mismo board simultáneamente). Se protege read-modify-write en appendLearningsSection/appendLearning/setLearnings (learnings.md), y en updateTask/appendTaskNote/setTaskStatus vía withFileLock + _freshTask que re-lee del disco dentro del lock para no clobberar cambios de otro proceso. No cambia formato de archivos persistidos. Tests: fix del caso serializes writers (unlink tras timeout), y dos tests multi-proceso concurrentes (appendLearning+appendTaskNote y appendLearningsSection+updateTask) verificando que no se pierde ninguna entrada y no quedan .tmp/.lock residuales. Build/typecheck/tests verdes (101 tests core).
