## Description

Hallazgo del usuario: el board de `http://localhost:4310` "se ve mal" y muestra muchos errores de YAML. Causa: el contenedor `agentsprint` corría una imagen del 2026-08-26 (dos meses atrás) sobre el mismo `.agentboard/` que el código actual. Ese esquema viejo no conoce los asignados especialistas ni los eventos `review`, así que ocultaba 13 tareas (TK-31, 33, 37…46) con un mensaje que culpaba al YAML. Además habría borrado el historial de reviews al reescribir una tarea. Por el mismo `:4310/mcp` entraba opencode, así que también trabajaba contra la versión vieja. Otros problemas: el contenedor corría como root (dejó `.agentboard/metrics/` de root en 3 repos), no tenía `git` (los enlaces a commits fallaban), `.dockerignore` no excluía `packages/*/node_modules` ni `dist`, el puerto estaba publicado en la LAN sin token, y `../docker-compose.yml` (notely-stack) definía otro board en el mismo puerto.

## Acceptance criteria

- [x] Un solo origen para el board en Docker: `AgentSprint/docker-compose.yml` (+ override); el servicio duplicado de `../docker-compose.yml` queda fuera con una nota
- [x] `pnpm docker:up` reconstruye la imagen desde el checkout, la marca con el commit y reinicia el contenedor
- [x] La imagen corre como `node` (uid 1000), trae `git` y usa `tini`; `.dockerignore` excluye `node_modules` y `dist` anidados
- [x] `GET /api/health` devuelve `{ version, commit, builtAt }` y `agentboard serve` imprime el build al arrancar
- [x] Un archivo de tarea que no se puede leer dice por qué (campo + aviso de servidor más viejo, o error YAML) en vez de culpar siempre al YAML; test
- [x] El puerto se publica solo en loopback, con `--allowed-host` para localhost y 127.0.0.1
- [x] Docs: tabla "Which AgentSprint am I talking to?" en docs/installation.md, README y CHANGELOG
