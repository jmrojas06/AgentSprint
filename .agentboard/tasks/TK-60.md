  - packages/cli/src/index.ts:1104-1106 (installContextHook on win32): the hook becomes 'cmd' '/c' 'npx' '-y' '@jmrojas06/agentsprint-cli@0.2.0' context ... --hook. Claude Code runs command hooks in Git Bash, or in PowerShell when Git Bash is missing (code.claude.com/docs/en/hooks, 'Exec form and shell form'). In Git Bash, MSYS path conversion can rewrite '/c' to 'C:/'. In PowerShell, a quoted 'cmd' followed by arguments is a parse error unless prefixed with &. Hooks run in shell form, which resolves npx.cmd by name, so the cmd wrapper is not needed. Fix: build the hook from cliLauncher(entry, 'linux') (plain 'npx' '-y' ...) and keep cmd /c only for .mcp.json. Update the test at cli.test.ts:92-100 and criterion 2. Not reproducible on Linux; please confirm on Windows.
  - docs/quick-start.md:52-58: it says Light means 'your main session does the task itself' and that only Full sends work to a read-only reviewer. But SERVER_INSTRUCTIONS (packages/mcp/src/index.ts:34) tells every session: 'Work in Review passes a review gate: launch the reviewer subagent'. So a Light run still launches code-reviewer for each task it moves to Review. The resume prompt itself dispatches nothing. Fix: add one clause to Light (for example 'the read-only reviewer still checks each task in Review') or make the instruction conditional.
  - Minor, non-blocking: packages/core/src/context.ts. On a board that holds only the samples, the closing 'How to continue' step 1 still says 'take the first task of Next up' (TK-1), which contradicts the New board section above it. Optional fix: skip or reword that step while the New board section is shown.
