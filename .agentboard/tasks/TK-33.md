## Description

El server expone rutas mutantes (POST/PUT/PATCH/DELETE) sin ninguna autenticación: cualquier proceso local puede modificar el board. Añadir autenticación opcional por token: flag CLI `--token <secret>` o variable de entorno AGENTBOARD_TOKEN. Cuando está configurado, todas las rutas mutantes exigen header `Authorization: Bearer <token>`; las lecturas GET pueden quedar abiertas por defecto, pero se debe documentar la opción `--token-all` que exige token también en GET. Sin token configurado el comportamiento debe ser exactamente el actual (sin auth). La UI debe pedir el token al usuario cuando reciba un 401, guardarlo en localStorage y reintentar.

## Acceptance criteria

- [ ] `agentboard serve` acepta `--token <secret>` y también lee la variable de entorno AGENTBOARD_TOKEN como alternativa equivalente
- [ ] Con token configurado, toda ruta mutante (POST/PUT/PATCH/DELETE) sin header `Authorization: Bearer <token>` válido responde 401; con token válido responde normalmente
- [ ] Las rutas GET quedan abiertas por defecto cuando solo se usa --token; existe la opción documentada `--token-all` para exigir token también en GET
- [ ] Sin --token ni AGENTBOARD_TOKEN, el comportamiento es idéntico al actual (sin auth, cero cambios en las respuestas)
- [ ] La UI detecta una respuesta 401, muestra un prompt/petición del token y lo guarda en localStorage reintentando la petición automáticamente
- [ ] El token nunca se imprime en logs ni en mensajes de error del server; README/docs del server documentan las opciones --token y --token-all
