## Description

Al mover una tarea de estado, el asignado debe cambiar automáticamente según el mapping: Backlog/To Do→scrum-master, In Progress→dev, Review→review, Done→perfect. Evita confusión sobre quién es el responsable actual. Implementar en core (setTaskStatus), con eventos en activity log, consistente entre CLI/API/MCP/UI.

## Acceptance criteria

- [ ] Mover una tarea a Review cambia automáticamente assignee a 'review'
- [ ] Mover a Done cambia assignee a 'perfect'
- [ ] Mover a In Progress vía task_status (sin claim explícito) cambia assignee a 'dev'; task_claim sigue teniendo prioridad y puede forzar otro agente
- [ ] Mover a To Do o Backlog cambia assignee a 'scrum-master'
- [ ] El cambio de assignee genera evento 'assignee' en el activity log de la tarea
- [ ] El comportamiento funciona igual desde CLI, API REST y tool MCP task_status
- [ ] Tests que cubren cada transición
