## Description

Implementar auto-asignado del `assignee` según el estado de la tarea. Al cambiar el `status` por cualquier vía (PUT /api/tasks/:id, PATCH /api/tasks/:id/status, MCP task_status/task_claim, o updateTask/setTaskStatus en core) el sistema debe reasignar automáticamente antes de persistir según el mapping:

- Backlog → scrum-master
- To Do → scrum-master
- In Progress → dev (genérico; task_claim puede forzar otro agente y no debe ser pisado)
- Review → review
- Done → perfect

El cambio debe generar evento `assignee` en el activity log además del evento `status`. task_claim mantiene prioridad (no pisa assignee que fija el claim) y no rompe lock exclusivo ni idempotencia.

## Acceptance criteria

- [x] Mapping Backlog→scrum-master, To Do→scrum-master, In Progress→dev, Review→review, Done→perfect aplicado en setTaskStatus/updateTask antes de persistir
- [x] task_claim tiene prioridad y no es sobreescrito por el mapping genérico; lock exclusivo e idempotencia intactos
- [x] Cambio de assignee genera evento `assignee` en activity además de `status` (visible en GET /api/tasks/:id/activity)
- [x] Endpoints PATCH /api/tasks/:id/status, PUT /api/tasks/:id y MCP tools task_status / task_claim reflejan el mapping
- [x] Tests en packages/core/src/activity.test.ts (o nuevo file) y packages/server/src/server.test.ts cubren cada transición y verifican assignee + activity
- [x] Build, typecheck y test verdes (core, server, mcp, web, cli)
