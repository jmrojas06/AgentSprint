## Description

Hallazgos no bloqueantes del `code-reviewer` al revisar TK-39 y TK-40 (ver sus notas):

1. `reviewTask` (packages/core/src/storage.ts ~739) y `appendTaskNote` (~707) no limpian saltos de línea del nombre del revisor/autor: un nombre con `\n## …` mete un encabezado suelto en las notas y en el log de actividad, y la línea de actividad se pierde en la siguiente reescritura. El journal ya normaliza el autor; hacer lo mismo aquí.
2. `agentboard connect` (packages/cli/src/index.ts ~787) cita las rutas del hook con `JSON.stringify`, que no es seguro para la shell: una ruta con `$` o una comilla invertida rompe el hook o ejecuta una sustitución.
3. `reviewerFor` (packages/core/src/dispatch.ts ~64) pasa los tags a minúsculas para detectar UI pero no para los agentes de decisiones (`ideas`, `creative`), así que un agente con tag `Creative` sí recibe revisor.

## Acceptance criteria

- [x] Los nombres de autor/revisor en `reviewTask` y `appendTaskNote` se normalizan a una sola línea (como en el journal); un test con `"bot\n## x"` deja notas y actividad intactas
- [x] El comando del hook de SessionStart cita las rutas de forma segura para la shell (comillas simples con escape); un test con una ruta que contiene `$` y una comilla invertida produce un comando que no expande nada
- [x] `reviewerFor` compara los tags de agentes de decisiones sin distinguir mayúsculas; test con tag `Creative`
- [x] `pnpm -r test`, `pnpm typecheck` y `pnpm lint` en verde
