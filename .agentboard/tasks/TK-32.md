## Description

Hallazgo de review de TK-17: `_atomicWrite` en core escribe a un archivo temporal de nombre fijo `${file}.tmp` y luego lo renombra. Sin lock, dos procesos escribiendo el mismo archivo pueden colisionar en el mismo .tmp: uno sobrescribe al otro y se pierden entradas (riesgo real con múltiples agentes trabajando el board). Fix: usar un nombre tmp único por proceso (pid + random) para el archivo temporal, y opcionalmente añadir un lockfile simple para serializar escrituras al mismo destino. Mantener total compatibilidad con el formato actual de los archivos (sin migraciones).

## Acceptance criteria

- [x] El archivo temporal usa nombre único por proceso (p.ej. `${file}.${pid}.${random}.tmp`), eliminando la colisión entre procesos concurrentes
- [x] El archivo temporal se limpia (rename atómico a destino o delete) también en caso de error (try/finally)
- [x] Opcionalmente existe un lockfile simple que serializa escrituras sobre el mismo destino, sin deadlocks (el lock se libera siempre)
- [x] El formato del archivo escrito no cambia: los archivos .agentboard existentes siguen siendo legibles y las suites de tests actuales pasan sin migración
- [x] Existe un test que simula dos escrituras concurrentes al mismo archivo y verifica que ambas terminan con el contenido esperado (sin entradas perdidas)
