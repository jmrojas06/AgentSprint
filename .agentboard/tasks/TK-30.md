## Description

Hoy no hay CI que valide los PRs, así que regresiones (tests rotos, typecheck fallido, build roto) pueden llegar a develop/main sin detectarse. Crear un workflow GitHub Actions separado (.github/workflows/ci.yml — NO tocar el docs.yml existente de Pages) que en cada PR ejecute: install (pnpm), lint, typecheck (`pnpm -r typecheck`), tests (`pnpm -r test`) y build (`pnpm -r build`), sobre Node 20+, con caché de dependencias de pnpm para acelerar las ejecuciones.

## Acceptance criteria

- [ ] Existe .github/workflows/ci.yml (workflow separado del docs.yml existente) que se ejecuta en cada pull_request
- [ ] El workflow ejecuta en orden: instalación de dependencias, `pnpm lint`, `pnpm -r typecheck`, `pnpm -r test` y `pnpm -r build`
- [ ] Se usa Node 20 o superior (matrix o versión fija >= 20) y pnpm con caché de dependencias (actions/setup-node cache: pnpm o actions/cache sobre la store de pnpm)
- [ ] Un fallo en cualquiera de los pasos marca el workflow como fallido (no hay continue-on-error)
- [ ] El workflow existente docs.yml sigue funcionando sin cambios funcionales
