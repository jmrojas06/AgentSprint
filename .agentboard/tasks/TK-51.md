## Description

Seguimientos de los reviews de TK-35 y TK-46: `createSprint` y `setSprintStatus` no usan lock, así que dos procesos pueden crear el mismo id de sprint; y los nombres de actor de `createTask`/`updateTask` (`opts.actor`) y `lockTask` llegan sin normalizar a las líneas de actividad, donde un salto de línea o un `|` rompe el formato y la línea se pierde en la siguiente reescritura.

## Acceptance criteria

- [x] La asignación de id de sprint y la escritura de sprints ocurren bajo un lock de board (como `task-ids.lock`); un test con dos procesos creando sprints a la vez no repite ids
- [x] Todo actor que llega a una línea de actividad pasa por un único saneador: una línea, sin `|` (reemplazado), recortado; test con `"bot | x\ny"` en createTask, updateTask, lockTask, notas y reviews
- [x] Las líneas de actividad existentes siguen leyéndose igual (sin migración); la suite completa pasa

## Notes

- [2026-10-21T21:01:23.560Z] (fixer) Root cause 1: createSprint took its id from the in-memory sprint map (no lock, no disk re-read), and updateSprint/setSprintStatus wrote back the cached copies of every sprint they touched. A second store or process therefore reused ids (repro: 4 processes x 8 sprints kept only 17 of 33 files) and reverted other processes' edits. Fix: all three now run under a board-wide `.agentboard/sprints.lock` (withFileLock, like task-ids.lock), re-read sprints/ inside it, and _nextSprintId also counts sprint-N.md files it cannot parse. Twin fix: _requireSprint re-syncs on a miss, so a stale store can file a task into a sprint another process created.
- [2026-10-21T21:01:23.560Z] (fixer) Root cause 2: actors reached serializeActivity raw. The old oneLine helper (notes/reviews only) collapsed whitespace but kept `|` and allowed a blank name, and createTask/updateTask did no cleanup at all. Fix: oneLine became sanitizeActor (one line, `|`→`/`, trimmed, blank→'user'). It is applied in _createTaskUnlocked and _updateTaskUnlocked (the choke point for update/status/checklist/lock/unlock/notes/reviews), plus the note and review prefixes. lockedBy keeps the exact name, so ownership checks still match. Read path untouched, so existing lines parse as before.
- [2026-10-21T21:01:23.560Z] (fixer) Tests: packages/core/src/safewrites.test.ts (15 tests). Red on the HEAD storage.ts (12 failures; the multi-process test was red against the old dist), green after the fix. Verified: core 267/267, server 65/65, mcp 56/56; typecheck clean for core, server, mcp and cli; eslint clean on my files. `pnpm typecheck` fails only in packages/web Overview.tsx (`ReviewSection` missing), the designer's in-progress file, unrelated.
