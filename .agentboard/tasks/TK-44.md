## Description

Hallazgo usando AgentSprint sobre sí mismo: `sprint_dispatch` puso TK-36 (sin descripción ni criterios, creada en el board equivocado) en la Wave 1 para `developer`, y `agentboard lint` dijo que el board estaba sano. Un subagente no puede entregar «todos los criterios» si no hay ninguno. Arreglo: una tarea pendiente sin criterios de aceptación queda bloqueada en el plan de dispatch con un motivo claro (y sus dependientes esperan por ella), y lint lanza un warning `NO_ACCEPTANCE_CRITERIA` para las tareas que no están en Done.

## Acceptance criteria

- [x] `planDispatch` no pone en ninguna wave una tarea pendiente sin criterios de aceptación: sale en Blocked con el motivo `no acceptance criteria — add them before dispatching`
- [x] Las tareas que dependen de una tarea sin criterios salen como bloqueadas (`waits on blocked …`) en vez de despacharse
- [x] `lintProject` emite un warning `NO_ACCEPTANCE_CRITERIA` para cada tarea que no está en Done y no tiene criterios; las tareas en Done no generan warning
- [x] Tests en dispatch.test.ts y lint.test.ts cubren los tres casos
