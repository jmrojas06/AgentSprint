## Description

Hoy el humano revisa abriendo archivos o el board. Queremos que la sesión principal de Claude Code le pregunte en el chat. Hace falta una fuente única que diga, por tarea en Review, qué veredicto tiene y si sigue vigente, y una forma segura de registrar la decisión humana. La lógica de "aprobada desde su último cambio" ya existe en la web (packages/web/src/ui.ts, reviewState/approvedSince…) y debe vivir en core para que la usen todos.

## Acceptance criteria

- [x] core expone `buildReviewQueue(tasks, opts)` (en un módulo nuevo, sin fs) que devuelve por tarea: id, título, sprint, asignado, criterios hechos/total, último veredicto (quién, cuándo, resumen, hallazgos), `approvedSinceLastChange` y una recomendación (`approve` | `look` | `changes-pending`) con su motivo; la web usa esta misma lógica en vez de la suya
- [x] MCP: herramienta `review_queue` (filtros sprint/ids, salida compacta) y `review_decide` ({ id, decision: 'done' | 'changes', findings?, by? }) que mueve a Done o registra `changes` con reviewer humano; nunca toca tareas fuera de Review
- [x] CLI: `agentboard review [dir] [--sprint n] [--json]` imprime la cola; `agentboard review [dir] --done TK-1,TK-2` y `--changes TK-3 --finding "…"` aplican decisiones
- [x] API: `GET /api/review-queue` con el mismo resultado; tests en core, mcp, cli y server
