## Description

Unificar el estilo y detectar errores estáticos en todo el monorepo. Hoy no hay linter común, así que cada paquete (core, server, web, cli, mcp) puede divergir en estilo y arrastrar bugs evitables. Se debe configurar ESLint (flat config) o Biome a nivel de raíz cubriendo todos los paquetes, exponer un script `lint` en el package.json raíz que falle (exit code != 0) si hay errores, corregir todas las violaciones existentes para dejar el repo verde, e integrar un step de lint en cualquier workflow de CI ya existente.

## Acceptance criteria

- [x] Existe configuración de linter (ESLint flat config eslint.config.js o biome.json) cubriendo los paquetes core, server, web, cli y mcp
- [x] `pnpm lint` (o equivalente en package.json raíz) ejecuta el linter sobre todo el monorepo y termina con código != 0 si hay errores
- [x] No quedan violaciones sin corregir: la ejecución del script lint termina con exit code 0
- [x] Si existe CI (.github/workflows/*.yml), incluye un step que ejecute el lint en cada PR
- [x] El linter está declarado como devDependency y typecheck/tests existentes siguen pasando
