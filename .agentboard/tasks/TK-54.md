## Description

Hallazgo del ui-reviewer en TK-50 (ya existía antes): TaskModal no mueve el foco a sí mismo al abrirse, no está marcado como diálogo y no retiene el foco, así que Tab recorre el board de detrás (53 pulsaciones para llegar al título a 375px, y a 1440px no llega tras 60). Hay que usar el mismo stack de diálogos que el resto (`useDialogFocus`), conservando la devolución de foco de TK-50 y el comportamiento de Escape de TK-33. Detalles: el icono de doble check verde en el título de Close approved cuando una tarea falla, y el botón Copy spec que se parte en dos líneas a 375px.

## Acceptance criteria

- [x] TaskModal y NewTaskModal tienen role=dialog, aria-modal y un nombre accesible; al abrirse el foco entra (título o primer campo) y Tab/Shift+Tab se quedan dentro
- [x] Escape sigue cerrando solo la superficie de arriba (prompt del token, diálogo de Request changes, paleta) y la devolución de foco de TK-50 (tarjeta, fila o vecina) sigue funcionando
- [x] El diálogo de Close approved con fallos usa un icono de aviso en vez del doble check verde; Copy spec no se parte a 375px
- [x] Tests de foco para ambos modales; sin regresiones en la suite web; revisado a 375px y 1440px en claro y oscuro
