## Description

Hoy el usuario no podía saber qué AgentSprint estaba usando: un contenedor de hace dos meses en :4310, un MCP stdio con un dist viejo y un servidor local. `agentboard doctor [dir]` revisa el entorno y dice qué está mal y cómo arreglarlo, en una línea por chequeo (✔ / ⚠ / ✖) y con código de salida != 0 si hay errores.

## Acceptance criteria

- [x] Chequeo de board: resume `lintProject` (errores y warnings) y detecta archivos `.lock`/`.tmp` huérfanos y archivos de `.agentboard/` que no pertenecen al usuario actual
- [x] Chequeo de build local: si el CLI corre desde un checkout, avisa cuando algún `packages/*/src` es más nuevo que su `dist` (sugiere `pnpm build`)
- [x] Chequeo de servidores: consulta `/api/health` en las URLs dadas con `--url` (por defecto http://127.0.0.1:4310) y compara su `commit` con el HEAD del repo; avisa si difiere o si el servidor no informa commit (imagen anterior a TK-47) y sugiere `pnpm docker:up`
- [x] Chequeo de MCP: lee `.mcp.json` del proyecto y verifica que la entrada `agentsprint` apunte a un archivo que existe
- [x] `--json` devuelve los resultados estructurados; la lógica vive en core (`doctor.ts`) con tests unitarios y la CLI solo la imprime
- [x] docs/cli.md documenta el comando y la tabla de docs/installation.md lo menciona
