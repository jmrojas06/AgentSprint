## Description

El endpoint GET /api/git/commit-counts recalcula escaneando el git log completo en cada reload, lo que hace la UI lenta con repos grandes. Introducir una capa de caché en memoria con TTL corto (~10s) para la respuesta, con posibilidad de invalidación manual. Evaluar y aplicar el mismo patrón al endpoint GET /api/tasks/:id/commits si también lee del git log en cada petición. La invalidación manual debe ser accesible cuando el board detecta cambios (p.ej. tras escritura de tareas).

## Acceptance criteria

- [ ] GET /api/git/commit-counts devuelve respuesta desde caché en llamadas repetidas dentro del TTL sin re-escanear el git log (verificable por logs o timing: 2ª llamada < ~10ms)
- [ ] El TTL de la caché es configurable y por defecto ~10 segundos
- [ ] Existe un mecanismo de invalidación manual de la caché (endpoint o función exportada) documentado en el código
- [ ] Si aplica, /api/tasks/:id/commits usa la misma capa de caché con TTL equivalente
- [ ] Los tests cubren: hit dentro del TTL, expiración tras el TTL e invalidación manual; `pnpm -r test` pasa
